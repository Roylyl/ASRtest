# Security policy

Please do not publish an exploit, exposed credential, malicious model file, or unsafe archive-handling issue in a public issue. Use the repository's [private vulnerability report](https://github.com/Roylyl/ASRtest/security/advisories/new). The repository owner must enable GitHub private vulnerability reporting before a public release. If that form is unavailable, open an issue containing only a request for a private contact channel; do not include vulnerability details.

Reports should include the affected revision, reproduction steps, impact, and whether the issue requires a crafted model, audio file, log, or local filesystem state. Remove recordings, personal paths, signing material, device identifiers, and other private data before sharing evidence.

Only the current `main` branch is maintained. A maintainer should acknowledge a private report within seven days, confirm its scope, and coordinate disclosure after a fix or mitigation is available. Model accuracy differences and expected resource use are not security vulnerabilities unless they create a concrete availability, integrity, privacy, or code-execution impact.
